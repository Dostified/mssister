Google Drive API Data Disclosure

Transparency & Compliance Statement for Google OAuth Verification • Package: com.mukesh.mssister

Google OAuth Verification Summary:
MS Sister (Package Name: com.mukesh.mssister) uses the Google Drive API strictly for user-requested backup and restore of encrypted menstrual health data. MS Sister maintains a zero-server architecture — all data is encrypted on-device prior to transmission and uploaded directly to the user's personal, private Google Drive App Data folder. Neither the app developer nor any third party ever accesses, reads, or stores user data.

1. Why MS Sister Requests Google Drive Access

Menstrual health history is deeply personal. Traditional health apps store sensitive user data on centralized servers, creating privacy risks. MS Sister solves this by allowing users to back up their data directly to their own personal Google Drive storage space.

Google Drive API permission is requested solely to:

  • Save an encrypted backup file of cycle records and daily symptom logs into the user's private Google Drive storage.
  • Restore encrypted cycle history when a user switches to a new Android phone.

2. Specific OAuth Scopes Requested

MS Sister requests the minimal restricted OAuth scope required to perform backup and restore operations:

  • Scope: https://www.googleapis.com/auth/drive.appdata (or drive.file)
  • Purpose: Accessing only the application-specific private data folder (Application Data folder) created by MS Sister in the user's Google Drive. The app cannot read or access any other files or folders in the user's Google Drive.

3. End-to-End Local Encryption Mechanism

Data security is maintained at every step of the sync process:

  1. On-Device Payload Generation: Cycle dates, period durations, flow levels, pain scores, symptoms, and remedies are compiled into a JSON structure.
  2. Hardware Key AES-256-GCM Encryption: The JSON payload is encrypted locally using Android KeyStore Master Keys (`AES/GCM/NoPadding`).
  3. Direct Sync: The resulting cipher text payload is transmitted directly over HTTPS to Google Drive servers. Unencrypted health data never touches network sockets.
  4. Local Decryption: Only the MS Sister app running on the user's device (with access to the device's KeyStore secret key) can decrypt and parse the payload.

4. Compliance with Google API Services User Data Policy

Official Limited Use Declaration:
MS Sister's use and transfer to any other app of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

Limited Use Commitments:

  • No Third-Party Sharing: We do not share, transfer, or sell Google Drive user data to any third-party advertisers, data brokers, or external entities.
  • No Advertising / Marketing Use: Information retrieved from Google Drive APIs is never used for serving targeted ads, marketing campaigns, or re-targeting.
  • No Machine Learning / AI Training: Data accessed from Google Drive is never used to train artificial intelligence, large language models (LLMs), or machine learning models.
  • No Human Inspection: Human beings (including the app developer) do not read or inspect user backup files stored on Google Drive.

5. User Rights, Revocation & Data Deletion

Users possess complete control over their Google Drive backup files and authorization settings:

  • Deleting Backups from Drive: Users can delete the encrypted MS Sister backup file at any time by navigating to Google Drive > Settings > Manage Apps > MS Sister > Delete hidden app data.
  • Revoking OAuth Permissions: Users can revoke MS Sister's access to their Google account at any time via Google Account Permissions.
  • Disabling Sync in App: Disabling Google Drive Sync in MS Sister Settings immediately halts all cloud backup calls.
